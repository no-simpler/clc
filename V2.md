## 1. Mission (refined)

clc serves projects that need **plausible deniability of agentic usage** — or, more generally,
that do not want to commit an agentic "second brain" into their own version control, for
whatever reason.

For such projects clc provides **friction-less, separate version management in two cleanly
separated slices**:

- **Slice A — main code:** version-controlled in place, in the project's own git repo. The
  second brain **never enters it.**
- **Slice B — second brain:** *also* version-controlled, but **separately and centrally** — one
  git-backed store per machine holds the second brains of **all** enrolled projects, with
  configurable **auto-backup** (push to a git remote, e.g. a private GitHub repo; and/or write
  a local filesystem bundle blob, e.g. to an iCloud-backed path).

The end state: as an enrolled project evolves, its second brain evolves alongside it **mostly
automatically** (committed on the same cadence as main-code commits), and — with backup
configured — is **durably persisted across machines** without ever entering its project's VCS,
provided the user follows a few conventions (§5).

**Audience:** the owner (this machine's user) is the **prime** audience. clc happens to be
published; that is the **secondary** use case. Design for the owner's workflow first; keep it
clean enough to ship.

## 2. Where v1 stands today (baseline)

- **Second brain** = Claude-related files: `CLAUDE.md` at any depth + a root `/.claude/`
  directory. (Definition carries forward to v2 unchanged unless noted.)
- **Enrollment today** is ignore-only: `clc ignore` appends the two patterns to
  `.git/info/exclude` (local gitignore). `unignore` reverses it.
- **Storage today** is **timestamp-versioned file snapshots**:
  `~/.clc/saved/<basename>@<md5-of-abs-main-worktree-path>/<unix-ts>/…`. `save`/`restore`/
  `compare`/`diff` operate against the latest snapshot. `CLC_STORE` env var overrides the root.
- **Worktree management:** `new` / `rm` / `prune` / `pull` / `close`.
- **No config file.** Pure bash, git-only, no other deps. Snapshot test suite in `test/`
  (`run.sh` + `cases/` + `expected/`), CI on push/PR.

v2 keeps worktree management broadly as-is and **replaces the snapshot storage model** with a
git-backed central store plus enrollment, hooks, config, backups, and a cross-machine story.

## 3. Concepts & glossary

- **Second brain** — the Claude-related files of a project (see §2). Conceptually **repo-wide**
  (one per repo, keyed by its main worktree), not per-worktree.
- **Enrolled project** — a repo clc actively manages: locally-gitignored second brain + a
  registry entry + installed hooks + synced into the central store.
- **Central store** — a per-machine **git repository** holding every enrolled project's second
  brain, each mirrored under a HOME-relative path. The unit of version history for slice B.
- **Registry / manifest** — the index of enrolled projects, committed *into* the store (so it is
  portable and auto-backed-up). Maps each project (by HOME-relative path) to its metadata
  (origin remote URL, etc.). Doubles as the cold-start manifest.
- **Backup target** — a configured destination the store is pushed to: a **git remote** or a
  **local bundle** blob.
- **Managed worktree / peer worktree** — carried over from v1: the main worktree, plus
  convention-named peer worktrees (`<main>-<name>`).
- **Canonical brain source** — when multiple worktrees of one repo have divergent second
  brains, the worktree whose brain is authoritative for the store (see §6.1).
- **Sync** — the operation that re-materializes a project's second brain into the store and
  commits it (`clc sync`, or `clc sync --from-hook` from a git hook).

## 4. Architecture — anchored decisions

Each is **DECIDED** (the working default) unless marked otherwise, with rationale and the
trade-off accepted. The sharp, still-undecided questions live in §6.

### 4.1 Central store = a non-bare git repo  · DECIDED

The store is a normal (non-bare) git repo at `$XDG_DATA_HOME/clc/store`, whose **working tree
mirrors** each project's second brain under a HOME-relative path (human-browsable):

```
$XDG_DATA_HOME/clc/store/            # a git repo
  .clc/registry                      # the manifest (committed; see §4.3)
  Developer/clc/CLAUDE.md
  Developer/clc/.claude/settings.json
  Developer/halo/CLAUDE.md
  work/foo/.claude/...
```

Real git history replaces timestamp snapshots. Non-bare (vs bare) chosen because an owner-first
tool benefits from `cd $XDG_DATA_HOME/clc/store && ls` showing every brain laid out, and
cold-start "deploy" becomes a plain copy from a checked-out tree. *Trade-off:* a single shared
index → concurrent syncs must serialize (§4.10).

### 4.2 Copy-sync, not symlink  · DECIDED

Second-brain files live as **real, locally-gitignored files in the project worktree** (Claude
Code reads/writes them normally). Sync **copies** them into the store. Symlinks rejected: a
symlinked `CLAUDE.md` pointing into `~/.local/share/...` is *more* conspicuous (worse
deniability), bakes in machine-specific paths (breaks cross-machine), and blurs the commit
cadence (writes hit the store immediately, uncommitted).

**Sync must be delete-aware and subtree-scoped.** It re-materializes *only that project's
subtree* in the store (compute the file set, remove orphans with `git rm`, copy current files,
`git add -A <project-subdir>` — **never** the whole store) and commits. The naive "copy
survivors and commit" leaves deleted brain files orphaned in the store forever and risks
sweeping another project's in-flight changes. *This is the single most bug-prone area of v2.*

The executable spec (P2 implements this verbatim):

```
store_sync_project(rel, wt):            # rel = HOME-relative project path; wt = source worktree
  with_store_lock:                      # mandatory mkdir-lock (§4.10)
    F := collect_claude_files_in_dir(wt)   # current brain, paths relative to wt
    S := $store/$rel                       # this project's subtree in the store
    mkdir -p S
    T := git -C $store ls-files -z -- "$rel"     # currently-tracked files under the subtree
    for t in T:  if (t relative-to rel) ∉ F:  git -C $store rm -q -- "$t"   # drop orphans
    for f in F:  mkdir -p dirname(S/f); cp wt/f S/f; git -C $store add -- "S/f"
    git -C $store add -A -- "$rel"             # belt-and-suspenders, subtree-scoped ONLY
    if git -C $store diff --cached --quiet -- "$rel":  return NOOP   # unchanged → no commit
    store_commit "sync: $rel"                  # pinned identity, gpgsign=false, REAL date (§6.3)
```

**Invariants.** Every git path is `-- "$rel"`-scoped, so a concurrent project's in-flight subtree
is never staged or swept. The registry at `.clc/registry` (§4.3) lives outside every project
subtree and is never touched here. Empty `F` (brain deleted wholesale) collapses the subtree to a
"remove" commit — correct, not a bug. A project whose worktree is not under `$HOME` has no identity
(§4.4): **error, never guess.**

### 4.3 Registry / manifest, committed into the store  · DECIDED

A registry of enrolled projects lives **inside the store** (e.g. `.clc/registry`), committed and
therefore portable + auto-backed-up. Keyed by **HOME-relative path**; records per-project
metadata (origin remote URL, and whatever cold-start needs). It is simultaneously the **local
registry** (what's enrolled on this machine) and the **cross-machine cold-start manifest**.

**Format · DECIDED — line-oriented text** (HOME-relative paths only, no machine-specific
absolutes):

```
# clc registry — enrolled projects. Fields: <HOME-relative path> TAB <origin-url> [TAB <meta>…]
Developer/clc	git@github.com:me/clc.git
Developer/halo	git@github.com:me/halo.git
```

- TAB-separated; `#`/blank lines ignored; **sorted by path on every write** → deterministic output
  and line-clean cross-machine merges (two machines enrolling *different* repos = non-conflicting
  additions; the *same* repo = identical line, no conflict).
- Atomic write: render → `registry.tmp` → `mv`. Read with `while IFS=$'\t' read -r path origin _`.
  Extensible by appending columns (parser ignores extras). Bash 3.2-safe.
- Committed under the store lock as its **own** mutation (enroll/unenroll), distinct from
  brain-subtree syncs (§4.2).
- *Why not `git config -f` (despite §4.5):* a committed, cross-machine-synced manifest merges far
  more cleanly as sorted one-line-per-project text than as git-config stanzas. Config (§4.5) is
  local + single-writer, so git-config suits it; the registry is multi-machine, so text wins.

### 4.4 Identity = HOME-relative path  · DECIDED (move-handling via `clc relink`, §6.4)

A project's identity is its **path relative to `$HOME`** (e.g. `Developer/clc`). This is the
store mirror path and the registry key. Origin remote URL is a secondary disambiguator.

A stamped `clc.id` in `.git/config` was considered as a stable, move-proof identifier and **set
aside as the primary key**: a fresh clone has no `clc.id`, so identity must be reconstructible
from path+origin anyway; the ID would only buy surviving a silent local `mv`, and a *silent*
move across machines is itself a footgun. Moves are therefore handled by an **explicit
`clc relink`** — treated as a safety feature, not friction.

*Trade-off:* moving a repo needs an explicit relink. The deeper cross-machine move/clobber story
(the "smarter solution" the owner asked for) is **DECIDED** — surface-don't-apply guard-rails,
`clc doctor`/`relink`/`clone`/`adopt`, see §6.4.

### 4.5 Config via `git config -f`  · DECIDED

Config lives at `$XDG_CONFIG_HOME/clc/config` and is read/written with
`git config -f $XDG_CONFIG_HOME/clc/config …`. No custom parser; consistent with the project's
"git only, don't replicate git" ethos; gives sections, multi-values, comments, atomic writes for
free.

- **Backup targets as subsections:** `[clc "backup.<name>"] kind = remote|bundle; url = …;
  path = …; keep = <n>`. Enumerate via `git config --get-regexp '^clc\.backup\.'`.
- **Paths stored `~`-relative**, expanded at read (the config is YADM-tracked across machines,
  §5; a bundle target's absolute path is host-class-specific — skip-with-warning when it
  doesn't exist on this host).
- **All reads guarded** (`git config … || true`): under `set -euo pipefail`, a missing key
  exits non-zero. v1 already models this discipline (`core.worktree`).

### 4.6 XDG locations  · DECIDED

| Kind | Location | Holds |
|------|----------|-------|
| config | `$XDG_CONFIG_HOME/clc` (`~/.config/clc`) | `config` (YADM-trackable) |
| data | `$XDG_DATA_HOME/clc` (`~/.local/share/clc`) | `store/` (git repo) + registry |
| state | `$XDG_STATE_HOME/clc` (`~/.local/state/clc`) | locks, sync/backup logs |

Defaults follow the XDG spec when the env vars are unset. **`CLC_STORE` override retained** (used
heavily by the test harness for isolation; also back-compat).

### 4.7 Enrollment, graduated  · DECIDED

`clc enroll` graduates the v1 ignore-only flow into:

1. Local-gitignore the second brain (existing `cmd_ignore` logic).
2. Register the project in the manifest (§4.3).
3. Install hooks (§4.8).
4. Initial sync into the store (§4.2).

`clc unenroll` reverses all four. Keep `ignore` / `unignore` as **aliases** for the gitignore-only
step (back-compat + the "I just want the ignore, not the machinery" case).

### 4.8 Hooks  · DECIDED (set), cadence best-effort

Install **`post-commit`** (primary) + **`post-merge`** (covers fast-forward `pull` + merge
commits) + **`post-checkout`** (covers worktree population). Each is a thin, **idempotent,
fail-safe, non-blocking** shim that calls `clc sync --from-hook` and **never** blocks the user's
`git commit` (no network in the foreground; post-commit's exit code is ignored by git, but a
*hanging* hook would freeze the commit — so the backup push is backgrounded, §4.9).

Installed **without clobbering** existing user hooks: append a clearly **marked block** to any
existing hook (compose with husky/lefthook/`core.hooksPath` — see §6.5).

**Cadence is best-effort.** `post-commit` fires on commit and `--amend`; `post-merge` on merge/
FF-pull; `post-checkout` on checkout. **`git rebase` does not fire these for replayed commits** —
if the brain changed mid-rebase, a manual `clc sync` is needed. Document this honestly: "synced
on commit/merge/checkout, best effort," not "every possible git operation."

### 4.9 Backups — configurable cadence  · DECIDED

**Decouple** "commit to store" (every sync; fast; local; always) from "push to backups."

- **Default: debounce** — push no more often than a reasonable interval (interval configurable).
- **Configurable to push-every-commit** for users who want it literal.
- **`clc backup`** forces an immediate push to all targets — the manual second line of defense.
- **Target kinds:**
  - **git remote** — `git push <remote>`. Cheap, incremental.
  - **local bundle** — `git bundle create <path> --all`, which **overwrites** a single blob.
    Since the store holds only **textual** second brains, the blob stays small (the
    growing-blob concern is bounded). Rotate atomically with a `.prev` copy (Nexus pattern:
    write `tmp` → rename current→`.prev` → rename `tmp`→current) so an interrupted bundle never
    leaves zero valid bundles.
- Push is **backgrounded and fail-safe**: a target being offline/unauthed warns + logs
  (`$XDG_STATE_HOME/clc/`), never blocks, never fails the commit. **Staleness** (last successful
  push per target + age) is surfaced in `status` / `doctor`.

*Borrowed from `~/Documents/Nexus`:* post-commit → bundle blob with `.prev` rotation
(`cp -p current → .prev`, write `tmp`, atomic `mv`), fail-safe backgrounded push
(`( … ) & disown; exit 0`), `osascript` macOS notification on failure. *Dropped from Nexus:*
encryption (not needed for clc) and the "never add a git remote" rule (clc *wants* git-remote
backups). **Net-new (Nexus does *not* have these):** Nexus pushes on *every* commit with **no
debounce** and takes **no lock** — it explicitly assumes single-machine, last-writer-wins. clc's
debounce (this section) and mkdir-lock (§4.10) are therefore designed and tested fresh, not lifted.

### 4.10 Concurrency  · DECIDED

Every store mutation takes a **mandatory advisory lock** (mkdir-based for macOS portability — no
`flock` dependency) under `$XDG_STATE_HOME/clc/`. Concurrent agentic commits across worktrees/
repos all fire hooks that touch the store's single index; without the lock a loser hits
`fatal: Unable to create '.../index.lock'`. Combined with subtree-scoping (§4.2), this keeps
concurrent syncs correct.

### 4.11 Determinism for the test harness  · DECIDED

The snapshot suite is keyed on deterministic `clc` output (today only the save timestamp and
`@<md5>` are normalized). A git-backed store introduces commit SHAs, author/committer dates, and
ordering. The resolution (full design in §6.3, now DECIDED): store commits keep **real wall-clock
dates** in production; the **fixed clc identity + `commit.gpgsign=false`** are stamped once into
the store's own `.git/config`; routine output (`status`/`doctor`) is **content-derived, not
history-derived** so it never surfaces SHAs/dates; and the harness pins
`GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` in fixtures plus a single shared SHA-scrub in `run.sh`.
**Any phase that introduces store commits ships its normalization in the same phase** — otherwise
the suite goes red. This is a first-class roadmap dependency, not an afterthought.

## 5. Conventions the user must follow

For the seamless cross-machine experience to hold:

1. **Uniform HOME-relative repo paths across machines.** A repo at `~/Developer/clc` on one
   machine is at `~/Developer/clc` on every machine. The HOME-relative path is the identity
   (§4.4); divergence is surfaced by `clc doctor`, never silently reconciled.
2. **YADM-track `~/.config/clc`** (or otherwise sync it). Config is portable by design
   (`~`-relative paths); host-class-specific targets (e.g. an iCloud bundle path) are skipped
   with a warning where they don't apply.
3. **Configure at least one backup target.** Without it, the central store is not durable beyond
   the local disk.
4. **Enroll/unenroll/relink/move via clc** — don't hand-edit the store or `.git/info/exclude`;
   let clc keep the registry, hooks, and store consistent.
5. **Edit the second brain in the main worktree.** The brain is repo-wide; a commit in *any*
   worktree syncs *that worktree's* brain to the store (§6.1). Peer commits still sync — but
   (a) clc prints a warning when the brain is synced from a peer, and (b) editing *divergent*
   brains in **multiple peers simultaneously is unsupported user-error**: last commit wins, and
   recovery is via the store's git history. clc intentionally adds no machinery to reconcile
   concurrent peer brains.

**Cold-start on a fresh machine** (target flow; details in §6.4 / P7):

1. Restore the store from a backup (`git clone <remote>` or from the bundle blob).
2. clc reads the manifest (§4.3).
3. For each enrolled project, clone its origin to its HOME-relative path — **guarded, never
   clobber** a non-empty directory.
4. Deploy the second brain into each worktree (copy from store) + local-gitignore it.
5. Install hooks.
6. `clc doctor` surfaces any drift (missing repos, path mismatches, stale backups).

## 6. Open / high-risk design areas

These each needed a **dedicated design pass** before their dependent implementation phase. Ordered
by risk. **All are now resolved** (§6.3 in the 2026-06-07 P1/P2 pass; §6.1/§6.2/§6.4/§6.5 in the
2026-06-07 full-runway pass) and are retained below as DECIDED for the record — no OPEN items
remain.

### 6.1 Canonical-brain semantics under multi-worktree auto-sync  · DECIDED

The brain is repo-wide, but peer worktrees can have **divergent** brains checked out. A commit in
*any* worktree fires the shared hook → which brain becomes canonical?

**DECIDED — current-worktree-wins (whichever worktree committed).** `clc sync --from-hook` resolves
the brain from `$PWD`'s worktree (`git_current_worktree`, clc.sh:139) and passes it as the source
`wt` to `store_sync_project`; `rel` stays the **repo identity** (the *main* worktree's HOME-relative
path, §4.4). The store mirror path is repo-wide and independent of which worktree sourced the brain,
so **no §4.2 algorithm change is needed** — the spec already parameterizes the source worktree.

- **Warn on a non-main source.** When the committing worktree is a *peer*, sync still proceeds but
  prints a single non-alarming warning line (surfaced through the git hook's stderr): the brain was
  synced from a peer, and the main worktree is the recommended place to edit it. Warning only — the
  store's git history is the recovery net.
- **"Oscillation" is declared a non-goal, not a bug.** Store HEAD = the most recent brain committed
  in *any* worktree, which is exactly the intended semantics. We deliberately ship **no**
  oscillation-avoidance machinery (no main-canonical promotion dance); simplicity over cleverness.
  This rests on the §5.5 convention — edit the brain in main; don't run divergent brains in multiple
  peers at once. Unblocks P5.

### 6.2 Async / coalesced backup-push mechanics + testability  · DECIDED

Backgrounding a push from a git hook so it (a) survives the parent shell exiting, (b) never
blocks/hangs the commit, (c) leaves no zombies, (d) logs failures, **and** (e) is
**deterministically testable**.

- **Backgrounding (Nexus pattern, §4.9).** After the local store commit, the push runs as
  `( push_all_targets ) >/dev/null 2>&1 & disown`, then the sync path `exit 0`s regardless. The
  subshell survives the parent git process, never blocks/hangs the commit, and leaves no zombies
  (disown + a cleanly-exiting subshell; git reaps).
- **Debounce state (§4.9).** Per-target last-success stamp at
  `$XDG_STATE_HOME/clc/backup/<name>.stamp` (epoch). A target is skipped when
  `now - stamp < interval` (default 15 min, configurable). `clc backup` ignores the debounce
  (forces all targets). Success rewrites the stamp; failure appends to
  `$XDG_STATE_HOME/clc/backup.log` (+ optional macOS `osascript` notify, per Nexus).
- **Two determinism seams** — the single async/time injection points, mirroring §6.3's `GIT_*_DATE`
  pinning:
  - `CLC_SYNC_SYNC=1` → the push runs **synchronously** (no `& disown`) so the harness can capture
    its output and exit status.
  - `CLC_NOW=<epoch>` → **all** wall-clock math (the debounce comparison; backup-staleness age in
    `status`/`doctor`) reads `CLC_NOW` instead of `date +%s`. Backup staleness is the *one* place
    wall-clock would otherwise leak into routine output (§6.3 keeps everything else
    content-derived); `CLC_NOW` makes that line snapshot-stable.

Unblocks P6; P6 ships both seams **with** its tests (§6.3 same-phase rule).

### 6.3 Store-commit determinism vs the snapshot harness  · DECIDED

This is the make-or-break for every later phase's green-ness. Resolution, in priority order:

1. **Routine output is content-derived, not history-derived.** `status`/`doctor` report sync
   *state* — `in-sync` / `drifted` / `never-synced` — computed by diffing the worktree brain
   against the store HEAD mirror (reuse the v1 `_compare_claude_files` machinery). No SHAs, no
   dates, no relative times ("3 minutes ago"). This makes the common output **snapshot-stable by
   construction** and shrinks the normalization surface to almost nothing. *This is the key move.*
   (The lone wall-clock exception — backup-staleness age in `status`/`doctor`, introduced by §6.2 —
   is pinned in tests via the `CLC_NOW` seam.)
2. **Production store commits keep real wall-clock dates** (meaningful "when did the brain
   change" history — the whole point of git history over v1's timestamp snapshots). The fixed clc
   commit identity and `commit.gpgsign=false` are stamped **once** into the store's own
   `.git/config` at `store_init`, so no per-commit `-c` is needed and every store commit is
   unsigned with a stable author/committer name+email.
3. **Only explicit history commands** (a future `clc log`) surface SHAs/dates. The harness handles
   those two ways: (a) fixtures export `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` so dates are pinned;
   (b) one **shared** SHA-scrub in `run.sh`'s `normalize_output()` — generalizing today's
   per-case `sed -E 's/[0-9a-f]{7,}/<sha>/'` into the runner so cases stop hand-rolling it.

Ships in P2, the first phase with store commits (§8 rule). Registry formatting determinism is
handled by §4.3 (sorted-on-write).

### 6.4 Cross-machine path convention + move/relink + cold-start clobber-safety  · DECIDED

The most user-data-dangerous area — auto-cloning/moving real code repos is dangerous. Policy:
**surface, don't auto-apply.**

- **Invariants.** (1) Never overwrite or `mv` a non-empty directory. (2) Never auto-move a code
  working tree. (3) Every cross-machine reconciliation is an **explicit** command; `clc doctor`
  only **reports**.
- **`clc doctor` cross-machine checks (read-only).** Per registry entry: path missing locally →
  "missing (run `clc clone`/`adopt`)"; path exists but its origin URL mismatches the registry →
  "path/origin drift (run `clc relink`)"; a locally-enrolled repo absent from the registry →
  "unregistered". Reports + the suggested command; never acts.
- **`clc relink [<newpath>]`** (move handling, §4.4). Run after moving a repo: rewrite the registry
  key (sorted re-write, §4.3), `git mv` the store subtree to the new HOME-relative path, re-point
  `.git/info/exclude`, and reinstall hooks at the new location.
- **`clc clone` / `clc adopt`** (cold-start, P7). Iterate the registry: empty/absent dir →
  `git clone <origin> <path>` then deploy the brain + local-gitignore + install hooks; an existing
  dir that **is** the right repo (origin matches) → adopt (deploy brain + gitignore + hooks, no
  clone); an existing non-empty **wrong/unknown** dir → **skip + warn** (never clobber).

This is the "smarter move solution" the owner wanted. Unblocks P7.

### 6.5 Hook composition with pre-existing user hooks / `core.hooksPath`  · DECIDED

Repos already using husky/lefthook or `core.hooksPath` need a non-clobbering, composable install/
uninstall contract. **DECIDED — compose.**

- **Hooks dir resolution.** If `core.hooksPath` is set, install there (composes with husky/lefthook,
  which drive hooks through `core.hooksPath`); otherwise `$(git_main_gitdir)/hooks` (clc.sh:102).
  Hooks are per-`.git` and shared across worktrees → installed **once** at the main gitdir.
- **Marked block.** Each of `post-commit` / `post-merge` / `post-checkout` gets a block delimited by
  sentinels `# >>> clc managed >>>` … `# <<< clc managed <<<` wrapping a single fail-safe line
  (`clc sync --from-hook … || true`).
- **Compose, don't clobber.** Missing hook → create with shebang + the block, `chmod +x`. Existing
  hook → **append** the block (idempotent: skip if the sentinel is already present); never touch the
  user's existing content.
- **Clean uninstall.** Remove exactly the marked block by its sentinels; delete the file only if clc
  created it and nothing but a shebang remains.

Unblocks P3.

## 7. Migration (v1 → v2)

v1 has existing data in `~/.clc/saved/` on the owner's machine. Migration plan:

1. **Discover** clc-touched projects. **Primary truth:** presence of the local-gitignore of the
   second brain (the two patterns in `.git/info/exclude`). **Secondary discovery source:** the
   old store's `~/.clc/saved/*/full-path.txt` files, which record each repo's absolute path —
   these are the practical enumeration mechanism (we can't cheaply scan the whole filesystem).
   For each candidate path, **verify** via the local-gitignore signal before adopting.
2. **Register** each discovered project per the v2 approach (§4.3) and install hooks (§4.7).
3. **One-time second-brain commit** per project into the new store — **accepting the loss of all
   pre-migration version history** (the timestamp snapshots are not replayed into git history).

Ship a **modest `clc migrate`** helper — don't over-engineer it; the realistic user base beyond
the owner is small. (Lands in P8.)
